# Analytics

`@plausible-analytics/tracker` is bundled by Astro. Browser requests use
`/api/event`; Nginx forwards them to Plausible. No browser API key is required.

## Input

| Event            | Input / trigger                                                                  | Event properties                                        | Interactive       |
| ---------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------- | ----------------- |
| `pageview`       | Visible page load, navigation, BFCache restore; generated by SDK                 | `from`; `situationId`, `position` on `/for/*`           | Standard pageview |
| `section_view`   | Dominant homepage situation visible continuously for 1 second; once per document | `situationId`, `position`                               | No                |
| `section_dwell`  | Situation loses dominance, tab becomes hidden, or page is suspended              | `situationId`, `position`, `ms`                         | No                |
| `content_expand` | Code or objections popover opens                                                 | `situationId`, `position` when available, `contentType` | Yes               |
| `cta_click`      | Marked navigation / next-step link activated                                     | `placement`, `target`; situation context when available | Yes               |
| `install_copy`   | Successful clipboard write on `/for/*`                                           | `situationId`, `position`                               | Yes               |
| `package_click`  | Ecosystem package / alternative link activated                                   | `placement`, `target`, `package`                        | Yes               |

The SDK also sends built-in `engagement` requests for page time and scroll depth,
independently of custom `section_dwell` events.

Properties:

- `page`: current pathname, added to custom events and pageviews.
- `situationId`: section / situation ID; `position`: one-based index in `src/config/order.ts`.
- `ms`: visible interval duration. Excludes hidden time; includes the first qualifying second.
- `target`: internal path with query and fragment, or full external URL.
- `from`: document referrer classified as `home`, `internal`, `external`, or `direct` (absent). Acquisition referrer / UTM attribution remains SDK-managed.
- `contentType`: `code` or `objections`. Objections use `situationId=small-ecosystem`, without `position`. Initially open code produces no expansion event.
- `package`: package name. `placement` identifies the existing link's location:

| `placement`                                                | Location                                         |
| ---------------------------------------------------------- | ------------------------------------------------ |
| `header`                                                   | Shared desktop / mobile navigation               |
| `situation`                                                | Homepage situation link                          |
| `philosophy`, `home-start`, `objections`                   | Homepage Why, Getting started, objection answers |
| `situation-start`, `situation-next`                        | `/for/*` next steps                              |
| `ecosystem-package`, `ecosystem-alternative`               | Ecosystem package links                          |
| `ecosystem-start`, `ecosystem-next`, `ecosystem-situation` | Ecosystem next steps                             |
| `why-reference`, `why-next`                                | Essay references / return link                   |

Section geometry is evaluated on scroll / resize, at most once per animation
frame. A section qualifies when at least half of `min(section height, viewport
height)` is visible; the section with most visible pixels wins. Intervals shorter
than 1 second before the first view are discarded. Revisits add dwell without
another view. BFCache restores preserve seen IDs and restart the interval.

## Internal flow

```text
DOM actions / section timers → track(name, props) → adapter ─┐
SDK pageview / engagement ──────────────────────────────────┤
                                                          ↓
                        SDK fetch → /api/event → Nginx → Plausible
```

1. `src/components/layout/Analytics.astro` loads `src/client/analytics.ts` on marketing and Starlight pages. Producers import `src/lib/analytics.ts`; ESM initializes it once, before events.
2. Environment selects the adapter: production + exact origin `https://nanostores.net` → Plausible; development → `[Nano Stores]` console; other production origins → no-op. SSR does not initialize the SDK.
3. `src/lib/link-analytics.ts` delegates `click` / `auxclick` from `a[data-track]`, reads `data-placement`, `data-package` and situation attributes, and normalizes `target`. Keyboard, modified and middle clicks produce one event; canceled / right-button activations are ignored. Homepage popovers / timers and `/for/*` clipboard handlers call `track()` directly.
4. `track()` adds `page`, `situationId` and `position`, marks section observations non-interactive, then calls `adapter.send()`. The Plausible adapter omits null / undefined properties and converts remaining values to strings.
5. The SDK adds domain, full page URL, referrer and protocol fields, then sends JSON with `fetch(..., { keepalive: true })`. SDK pageviews bypass `track()` and get their properties through `customProperties`. Automatic outbound, download and form tracking are disabled; `localStorage.plausible_ignore="true"` suppresses SDK tracking.
6. The browser POST reaches Caddy, then Nginx. Nginx forwards body and User-Agent, preserves Caddy's sanitized X-Forwarded-For chain and appends its peer, strips Cookie / Authorization, and sends HTTPS to Plausible.

## Output

Browser: `POST https://nanostores.net/api/event`, `Content-Type: text/plain`.
Example JSON body (`v` is the SDK protocol version):

```json
{
  "n": "section_dwell",
  "d": "nanostores.net",
  "u": "https://nanostores.net/",
  "r": null,
  "v": 36,
  "i": false,
  "p": { "page": "/", "situationId": "islands", "position": "2", "ms": "1250" }
}
```

Nginx forwards to `https://plausible.io/api/event`: exact POST route, 16 KiB body
limit, SNI + certificate verification, connect / send / read timeouts of 3 / 5 / 5
seconds, no retries. Other methods return 405. Upstream DNS uses the container's
system resolver at startup; reload / restart Nginx after upstream address changes.

Trust boundary: [hplush/cloud](https://github.com/hplush/cloud/blob/main/roles/web/templates/web.container.j2)
binds container ports to host loopback; [Caddy sanitizes forwarding headers](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#defaults).
Keep port 8000 private; revalidate visitor IP forwarding after hosting changes.

## Setup and verification

- In Plausible, confirm `nanostores.net` and create goals matching the custom event names above; filter by `placement` / `target`. Do not also install the hosted snippet or enable automatic outbound tracking.
- `install_copy` measures copying, not completed installation. Custom `ms` values require export / a suitable report for averages.
- Replaced names: `deep_view`, `code_expand`, `section_cta_click`, `deep_cta_click`, `exit_click`, unused `toc_click`. The previous production adapter was no-op.
- Run [QA](qa.md); focused tests: `src/lib/analytics.test.ts`, `src/lib/section-analytics.test.ts`. Inspect dev console properties, hidden-tab / back-navigation intervals, copy success and single click delivery. On production, verify pageviews and custom events in the dashboard; localhost / preview builds must send nothing.

Proxy diagnostic, without recording an event:

```sh
curl --silent --show-error --include \
  https://nanostores.net/api/event \
  -H 'Content-Type: text/plain' \
  -H 'X-Debug-Request: true' \
  --data '{"name":"pageview","url":"https://example.invalid/","domain":"example.invalid"}'
```

Expected: HTTP 200 + visitor public IP. Normal HTTP 202 alone does not prove
recording; `x-plausible-dropped: 1` indicates rejection ([API reference](https://plausible.io/docs/events-api)).
For local TLS inspection, use a test-only trust bundle; retain production TLS verification.

Validation on 2026-10-15: 46-page build, formatting, types, 87 unit tests, 8 snippet
tests and Nginx diagnostic passed. Browser interactions checked at 1280×720 and
390×844. Manual Edge 155 / CDP verification passed: 28,916 ms hidden was excluded
from dwell; the resumed 23,026 ms visible interval matched the event. Back and
Forward restored the same documents (`pageshow.persisted = true`), without a
repeated `section_view`; resumed dwell excluded time away. Live dashboard / goal
setup remains pending.
